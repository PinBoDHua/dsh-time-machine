# 时光机设计说明

## 问题

Agent 的改动是**跨文件、长时间、半自主**的。现有的安全网分两类：

- 模型自觉：提示 Agent 小心、让它自己回滚。不可验证，失败时会把回滚也改坏。
- 事后审计：diff 卡片、会话日志、Git 状态。能看见，但不能**一键退回去**。

时光机把「可逆」从提示词里的愿望，变成宿主侧的一条强制能力：每次改变工作区的轮次都留下可恢复的状态，恢复本身也有安全点与失败回滚。

## 三条硬约束

1. **不污染用户仓库**
   用户可能正在编辑、暂存、解决冲突。Snapshot 不能 `git add` 到用户 index，不能写用户 objects，不能动 refs/HEAD。因此使用完全独立的 Git 目录与 refs。

2. **恢复必须可逆**
   恢复是一个破坏性写操作。任何恢复前必须有安全点；任何中途失败都必须能回到安全点；连回滚失败也要留下可读、可执行的日志。

3. **范围必须可解释**
   用户需要知道「这会动哪些文件」。因此恢复只覆盖会话工作目录子树；不跟随路径逃逸、不碰 `.git`、不删除忽略文件；所有路径在计划与执行两处校验。

## 为什么是影子 Git，而不是文件副本

| 方案 | 问题 |
|---|---|
| 整目录复制 | 每次轮次都复制全部文件，磁盘与 IO 不可接受；无法去重。 |
| 只复制文件工具点名的文件 | shell 改动、重命名、删除都覆盖不到；无法恢复目录级变化。 |
| 复用用户仓库的 stash/commit | 会动用户 index/refs，可能破坏正在进行的 merge；不可接受。 |
| 影子 Git 仓库 + 独立 index/refs | 内容寻址去重；完整覆盖增删改；不碰用户仓库；可用 `git gc` 回收。 |

实现要点：

- `GIT_DIR` 指向 `$DSH_HOME/.dsh-time-machine/repos/<key>/repo/.git`；
- `GIT_WORK_TREE` 指向快照根（会话在仓库内时是仓库根，否则是会话目录）；
- 使用私有临时 index，成功后才替换持久 index（只作为 stat 缓存）；
- `info/attributes` 写入 `* -text -filter`，禁止 CRLF/clean filter 改写，保留原始字节；
- `info/exclude` 写入默认排除与用户规则；工作区自己的 `.gitignore` 仍然生效；强制排除项（`.git/`、插件数据目录）排在用户规则之后，因此否定规则也无法把它们重新纳入；数据目录位于工作区内时按真实相对路径排除；
- 每个 checkpoint 是**无父提交**，只被 `refs/time-machine/checkpoints/<id>` 引用。删除引用后 `git gc --prune=now` 能真正回收；前后关系保存在元数据里。

工作区在 Git 子目录时，快照根取仓库根但 pathspec 限定为子目录：这样既继承仓库根的 `.gitignore`，又不会把工作目录外的文件纳入恢复范围。已验证用户仓库 index/HEAD/ref 逐字节不变。

## 数据模型

```text
Checkpoint {
  id            时间戳 + 随机后缀
  kind          auto | manual | safety | restore
  phase         before | after
  sessionId     创建它的顶层会话
  turn          轮次（自动点）
  label         仅手动点使用；系统点不存语言相关文案
  commit/tree   影子仓库对象
  previousId    展示/统计用，不是 Git parent
  stats         files / added / deleted / initial
  createdAt
}
```

每个工作区一个元数据 JSON，按新到旧排列。元数据写入是事务性的：磁盘写入失败时内存时间线与引用一起回退，不会留下指向已删除引用的“最新”记录。配置、journal 与影子仓库分目录存放，删除元数据不会删除用户工作区。

## 恢复状态机

```text
plan:
  快照当前 → 目标 tree 比较 → 路径/大小/冲突/符号链接预检
  → 生成 5 分钟计划 → 返回统计与样例

apply:
  重新快照，校验工作区未变化
  → 把当前 tree 落成安全点（独立 ref）
  → 写 journal（安全点、目标、模式、路径）
  → 写入文件（临时文件 + rename）
  → 删除文件（仅 exact 模式）
  → 再快照，逐路径校验目标 blob
  → 落「恢复后」checkpoint → 删除 journal

失败:
  按安全点回滚 → 再快照校验 → 删除 journal
  回滚也失败 → 保留 journal 与安全点 → 报错并给出 recover 命令
```

关键设计：

- **计划与执行分离**：用户先看到影响；执行时重新校验，避免 TOCTOU。
- **安全点用同一个 tree 新建 metadata**，不重复扫描，也不依赖临时对象。
- **journal 是恢复的一部分**，不是调试日志：它能让一次「回滚失败」在重启后继续收尾。
- **逐路径 blob 校验**（不是只看命令退出码）确保恢复真的写对了；校验失败同样回滚。
- **删除排在写入之后**；路径预检拒绝目录替换与大小写冲突，避免半删除状态。
- **符号链接**：POSIX 支持；Windows 上含符号链接写入/删除的计划直接拒绝，保证回滚能力。

## 记录时机

- `turn/start` 排队轮前快照；`tools/pre-execute` 等待它完成，防止工具写入早于基线；
- `agent/turn-stopping` 排队轮后快照；`turn/end` 兜底（中止/失败的轮次也能留下状态）；
- 内容与上一 checkpoint 相同则跳过（手动/安全点/恢复后除外）；
- 子代理不单独记录，避免同一工作区出现多份竞争时间线；父会话轮次覆盖它们的改动。

工具发起的恢复允许在**它自己的轮次**内执行：模型正等待工具结果，恢复不会与并行写重叠；其他会话仍在同一工作区运行时仍拒绝。人类面板/命令则要求会话空闲。

## 为什么有四种入口

- **标题栏面板**：日常入口，展示时间线与影响，适合人类做危险决定；
- **`/rewind`**：不打断输入、不产生模型消息，适合熟练用户与排障；
- **`time_machine` 工具**：让 Agent 在用户明确要求时参与回退，但只开放不删除的覆盖模式；
- **CLI**：宿主机不可用、面板报错或需要 recover 时的最后一条路径。

同源 HTTP 接口只接受回环请求；写操作需要状态接口下发的进程内控制密钥。恢复路径再经过三层校验（计划、执行、逐字节回读）。

## 刻意没做的事

- **不自动回滚**：是否回退是用户的决定；插件只负责让决定可执行。
- **不顺手提交用户仓库**：没有 `git add`、commit、stash，也没有隐藏分支。
- **不恢复忽略文件**：新快照不记录当前忽略规则命中的文件；恢复计划再按当前规则过滤旧快照中的条目。构建产物、依赖目录与日志不会被写回或删除。
- **不允许数据目录等于快照根**：这会让影子仓库把临时 index 与元数据拍进自己；启动时明确拒绝，而不是产生持续伪变化。
- **不在 0.3.0 分叉会话**：文件可退，对话不退；会话分叉需要新的身份与 UI，留到下一版。
- **不追求「零拷贝」**：影子仓库按内容去重，但首次快照仍会扫描工作区；用忽略规则与超时控制成本。

## 已知边界

- 会话在子目录、父仓库结构后来变化（例如后来才 `git init`）时，快照范围会变化。工作区 key 包含 workTree/prefix，因此会开启一条新时间线；旧数据保留但不会被新绑定复用，避免错误恢复。
- 轮次进行中切换工作目录时，轮前/轮后快照仍归属切换前的引擎；新目录从下一轮建立基线。旧引擎会在 `turn/end` 正确释放，不会永久显示忙碌。
- 多进程同时操作同一工作区（宿主 + CLI）没有跨进程文件锁；plan 引用有 10 分钟崩溃清理宽限，checkpoint 孤儿引用不自动删除，以免误删另一个进程正在写的快照。
- 大仓库初次快照可能超过 30s 默认超时；该轮记录失败但不影响 Agent。
- Windows 符号链接、子模块内部内容与 LFS 实体不保证字节级恢复。
- 恢复后对话上下文仍是旧的，继续前需要让 Agent 重新读取文件。
